# DuSu — Android app (TWA)

Runs the live DuSu web app **inside the app**, full-screen, on the device's own
Chrome engine (Trusted Web Activity). Because it *is* Chrome under the hood, the
Web Speech API (mic STT + TTS) works exactly like it does in the browser — unlike a
plain WebView, which breaks speech recognition.

This is a **separate module** from `../android-launcher` (which only kicked the user
out to external Chrome). Different package name (`com.dusu.app` vs `com.dusu.launcher`)
so both can be installed side-by-side.

- **Loads:** `https://dusu.ranabrothers.online/` (canonical). `asset_statements` also trusts
  the legacy `https://dusu.ruralrootcloud.com` so already-installed copies stay verified.
- **Package:** `com.dusu.app`
- **Min Android:** 6.0 (API 23; androidbrowserhelper 2.7.0 needs it) - **target API 36**

---

## 0. Notifications (since 1.1, versionCode 2)

DuSu's reminders are **server-decided Web Push**, not an in-app alarm. The manifest declares `DelegationService` (TWA notification delegation), so Chrome hands
each web-push notification to **this app**: the Android permission dialog, the notification channel and the notification itself belong to DuSu (small icon
`ic_notification_icon`, a white D-mark generated by `python3 gen_icons.py --notif-only`). The learner turns notifications on inside DuSu (More -> Notifications, or
the Home prompt after their first practice). The old static 4-hour alarm (`Notifications.kt`, `ReminderReceiver.kt`, `BootReceiver.kt`, `RECEIVE_BOOT_COMPLETED`)
is gone; `MainActivity.cancelLegacyReminders()` removes the alarm and the `dusu_reminders` channel from copies that were installed before.

**Delegation only works while the site is verified for this app** - the same Digital Asset Links check that hides the browser bar (section 3). A Play-installed
copy is re-signed by Google, so the **App signing key certificate** SHA-256 from Play Console (Setup -> App signing) must be listed too: owner dashboard ->
Android app link. Otherwise Chrome shows the URL bar AND keeps the notifications for itself.

## 0b. Building on the Linux box

```bash
export JAVA_HOME=/home/vibhanshu/android/android-studio/jbr ANDROID_HOME=/home/vibhanshu/Android/Sdk   # JBR 21 works; no JDK 17 needed here
cd android-twa && echo "sdk.dir=$ANDROID_HOME" > local.properties                                    # git-ignored
bash ./gradlew --no-daemon assembleDebug          # the wrapper is not executable: `bash ./gradlew`
bash ./gradlew --no-daemon bundleRelease assembleRelease   # needs keystore.properties (section 2) for a SIGNED AAB / APK
~/Android/Sdk/build-tools/36.0.0/aapt2 dump badging app/build/outputs/apk/debug/app-debug.apk | head   # versionCode / permissions
```
Without `keystore.properties` the release outputs are UNSIGNED - Play will not take them. The upload key is the one whose SHA-256 starts `EF:02:68:27` (it is what
`assetlinks.json` lists); if the `.jks` is lost, request an upload-key reset in Play Console, create a new key, and add its fingerprint on the dashboard too.

## 1. Build

Needs JDK 17 + Android SDK (same setup that builds `android-launcher`).

```bash
cd android-twa

# Quick test build (debug — self-signed, installable immediately):
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

# Release build (needs a keystore — see step 2):
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release.apk
```

Install on a phone (USB debugging on):

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The debug APK opens the site inside a **Custom Tab bar (browser X + URL)** and **always
will**: it is signed with Android's public debug key, which is never listed in
`assetlinks.json`. Use it only for `adb install` on your own phone. **Share only the
release build** (`assembleRelease`), and for Play-installed builds also add Google's
Play App Signing SHA-256 to the server's `ANDROID_CERT_SHA256` (comma-separated).

---

## 2. Release keystore (one time)

```bash
keytool -genkey -v -keystore dusu-release.jks -keyalg RSA -keysize 2048 \
  -validity 10000 -alias dusu
```

Create `android-twa/keystore.properties` (git-ignored):

```properties
storeFile=dusu-release.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=dusu
keyPassword=YOUR_KEY_PASSWORD
```

`assembleRelease` then signs automatically.

## 3. Full-screen (drop the address bar) — Digital Asset Links

Chrome hides its UI only when the site and the app vouch for each other.

**a. Get the APK's signing SHA-256:**

```bash
# debug key:
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey \
  -storepass android -keypass android | grep SHA256
# release key:
keytool -list -v -keystore dusu-release.jks -alias dusu | grep SHA256
```

Copy the `SHA256:` value (e.g. `AB:CD:...:EF`).

**b. Tell the server about it** — set an env var on the prod host (docker-compose `.env`):

```
ANDROID_CERT_SHA256 = AB:CD:...:EF
```

(Comma-separate multiple, e.g. your upload key **and** the Play App Signing key.)

The backend already serves the matching statement at
`https://dusu.ranabrothers.online/.well-known/assetlinks.json` from that env var (it is host-agnostic, so it
serves correctly on the legacy hostname too).
Verify after deploy:

```bash
curl -s https://dusu.ranabrothers.online/.well-known/assetlinks.json
```

The app side is already declared (`app/src/main/res/values/strings.xml` →
`asset_statements`).

**c. Reinstall the app.** On next launch Chrome verifies both directions and runs
DuSu edge-to-edge with no address bar.

---

## 4. Moving domains again

Update in three places:
1. `app/src/main/res/values/strings.xml` — `launchUrl`, `hostName`, `asset_statements` site.
2. Prod host env — keep `ANDROID_CERT_SHA256` (same cert), point the new domain's DNS.
3. The new domain must serve `/.well-known/assetlinks.json` (the backend route does).

---

## 5. Play Store (optional)

Play needs an **AAB**, not an APK:

```bash
./gradlew bundleRelease   # → app/build/outputs/bundle/release/app-release.aab
```

With Play App Signing, add **both** the upload-key SHA-256 and the Play-issued
app-signing SHA-256 to `ANDROID_CERT_SHA256`.
