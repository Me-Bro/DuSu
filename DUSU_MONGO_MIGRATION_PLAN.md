# DuSu -> shared MongoDB: the migration plan (2026-11-16)

Owner's request: "migrate our db to MongoDB as done for Yahin and RootEd ... we no longer need the current DuSu db ... after migration we test on the Play Store and deploy, then add 3 more free AI models."

Branch `feat/mongo-migration`, worktree `~/Desktop/DuSu-mongo` (cut from `main` = `8a53a71`). The uncommitted "AI busy" Phase 1 work stays on `fix/ai-busy-groq-budget` in `~/Desktop/DuSu` - the migration image must never contain it before its own live check.

## 1. What "as Yahin and RootEd did" means - and what it does not

Measured on this box (2026-11-16):

| | Yahin / RootEd | DuSu |
|---|---|---|
| Stack | Node, Mongo from day one | Python, **Postgres via SQLAlchemy** |
| Their move on 2026-11-11 (Yahin) | their own Mongo container -> shared `rooted-mongo` = **a dump/restore + a compose edit** | **a different database engine = a rewrite of the persistence layer** |

What DuSu copies from them (all documented in `~/Desktop/RootEd_ALL/shared-services/README.md` and `docs/PLAN.md`, step 6 "database migrations into shared Mongo, app by app (yahin, dusu, ...)"):

- ONE shared Mongo: container `rooted-mongo` (mongo:7.0.39, `--auth`, replica set `rs0` of one member, so multi-document transactions work), network `rooted-shared-net` (external), reached as `rooted-mongo:27017`.
- A database + a **scoped user per app**, made by `shared-services/scripts/create-app-db.sh <app> <env> --no-bucket` (DuSu has no S3 use, so no SeaweedFS restart): db `dusu`, user `dusu_prod_app` (readWrite on `dusu` only, `authSource=dusu`), URI `mongodb://dusu_prod_app:<pw>@rooted-mongo:27017/dusu?replicaSet=rs0&authSource=dusu`, written to `shared-services/creds/dusu-prod.env` (chmod 600, never printed).
- The compose shape (Yahin's `docker-compose.prod.yml`): the backend joins `[default, shared]`, `MONGODB_URI` is built in `environment:` from a `DUSU_MONGO_PASSWORD` in the root `.env`; the app's own DB container disappears.
- What the shared stack then gives DuSu for free: a nightly per-database `mongodump` into SeaweedFS (21:30 UTC) and a nightly copy offsite to Cloudflare R2. Today DuSu's Postgres has **no** automatic backup (only the manual `~/dusu-backups` dumps before deploys). That, and one container fewer on a RAM-tight host (15 GiB, ~4 GiB available), are the real gains.
- Their rules: a backup is not real until a restore drill passed; tests never touch the shared Mongo (Yahin's tests refuse any URI that is not a throwaway `*_test` database); never `source` shared-services' `.env` next to another project's compose.

## 3. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | A small Mongo data layer, `backend/app/store/`, with the **SQLAlchemy-2.0 surface the code already uses** (models, `select/update/delete`, `func`, `and_/or_`, `Session` with `get/add/delete/flush/commit`), unsupported constructs raise `NotSupported` (a `NotImplementedError` subclass). Models/services change their imports and the handful of SQL-only constructs; the logic is untouched | The code (and ~100 test sites) is written against exactly this surface; a hand-translation of ~600 statements is where subtle drift would come from. One tested component beats 600 hand edits. Documented as "Mongo with a SQLAlchemy-shaped surface", not as SQLAlchemy |
| D2 | Driver: **PyMongo 4.20 native async** (`AsyncMongoClient`). Not Motor (deprecated wrapper, last 3.7.1) | The maintained path |
| D3 | Database `dusu` on the shared `rooted-mongo`, scoped user, as in section 1. Never the root user | Same as Yahin / RootEd |
| D4 | Collection name = table name. `_id` = the natural primary key (single column); composite keys = a unique compound index. Integer ids stay integers (API paths and the client use them) from a `counters` collection (`find_one_and_update $inc`, outside any transaction, gaps are fine like sequences) | No client or API change |
| D5 | `DateTime` -> BSON date, tz-aware UTC (`tz_aware=True`), **millisecond** precision (Postgres had microseconds; the layer truncates on write so memory and DB agree). `Date` -> ISO string `YYYY-MM-DD`. `JSONB` -> embedded documents, normalised exactly like `json.dumps/loads` (string keys, tuples -> lists, an unserialisable value is an error as in Postgres) | Faithful round trips |
| D6 | Existing data IS migrated (a ~500-row ETL is cheap) even though the owner said the old DB is no longer needed: the nightly backups then cover real data from day one. Postgres stays up, unused, as the rollback for >= 7 days, then is retired with a last dump kept | Reversible |
| D7 | The production cutover and the retirement of Postgres happen **only on the owner's explicit go-ahead**; everything before that is branch-local or on scratch infrastructure | Production affects ~22 real learners |
| D8 | Tests run on a **scratch** `mongo:7` single-node replica set on an `--internal` Docker network (small cache), never on `rooted-mongo`. The harness refuses a URI that names `rooted-mongo` | Yahin's rule |
| D9 | One uvicorn worker stays the deployment (already assumed by the key ledger and the loops) | Lets in-process locks stand in for row locks; Mongo's own write-conflict detection remains the cross-process safety net |
| D10 | `MONGODB_URI` replaces `DATABASE_URL` / `DATABASE_SSL`. `db_enabled = bool(settings.mongodb_uri)` keeps the "stateless when unconfigured" behaviour. A `postgres...` value in the old variable is refused loudly | No silent fallback |

## 4. The data layer's contract: Postgres behaviour -> how Mongo reproduces it

Each row is a unit/differential test in `tests/store/`.

| Postgres / SQLAlchemy behaviour the code relies on | Emulation in `app/store` |
|---|---|
| `Session` = a transaction; `commit()` makes writes visible together | Writes buffer in the session; the first `flush()` opens a Mongo transaction, later reads in the session go through it (read-your-writes), `commit()` commits it. Reads before the first write are plain reads (READ COMMITTED-like) |
| `SELECT ... FOR UPDATE` waits for the other writer, then sees its result | Keyed in-process async lock per (collection, `_id`), taken at the locked read **before** the read, held to the end of the session; **writes also take their docs' locks at flush** (Postgres' UPDATE row lock); sorted acquisition + a lock-wait timeout (loud, breaks a deadlock). Mongo's WriteConflict stays the cross-process net |
| `FOR UPDATE SKIP LOCKED` queue claims (reminders, notification outbox) | Rewritten natively: atomic `find_one_and_update` claims, disjoint by construction, safe across processes |
| `ON CONFLICT DO NOTHING`, savepoint + `IntegrityError` ("insert, or take the winner's row") | `insert-or-ignore` via upsert `$setOnInsert`; `DuplicateKeyError` -> `IntegrityError` for the rest. (A duplicate key aborts a Mongo transaction - there is no savepoint - so the 5 savepoint sites are rewritten once, by hand, to this pattern) |
| `pg_advisory_xact_lock(hashtext(k))` | `await s.advisory_lock(k)`: the same keyed in-process lock, released at session end |
| NULL ordering: ASC = NULLS LAST, DESC = NULLS FIRST | Mongo is the opposite. Sorts on a column that can hold NULL are done in Python after the filter (data volumes are small); NOT NULL columns push down. `nulls_last()` honoured |
| `col != v` excludes NULL rows; `col IN (..)` never matches NULL | Compiled to `{col: {$nin: [v, null]}}`; `None` dropped from IN lists |
| `col == None` / `.is_(None)` | `{col: null}` (matches null and missing) |
| `LIKE`, `lower(col) == x` | anchored escaped regex; `$expr` + `$toLower` |
| `count/sum/min/max/avg/coalesce`, `group_by` | `count_documents`; `$group` pipelines; `coalesce` in Python |
| Unique indexes treat NULLs as distinct; Mongo treats null/missing as equal | every unique index over a nullable column is a **partial** unique index (`$type`) - checked per index when the model is ported |
| Partial indexes (`WHERE client_key IS NOT NULL`, `WHERE status='scheduled'`) | `partialFilterExpression` (`$type: "string"` / `$eq`) |
| `Base.metadata.create_all` + ad-hoc `ALTER TABLE` migrations | `init_db()` creates every registered model's indexes (idempotent, `create_index` is a no-op when equal). New fields need no migration (missing = default on load) |
| Autoincrement ids | `counters` collection, allocated at `add()` so `flush()` is not needed to learn an id |
| Dirty tracking incl. `flag_modified` on JSON | Snapshot compare at flush; `flag_modified` stays as a no-op import |
| FK cascades (child-first deletes) | already explicit in the code (`delete_rows`); ported to `delete_many` |

Not reproduced (and not needed): column length limits (the tests keep checking that every value the code writes fits the OLD widths, because a rollback to Postgres needs data that fits), `server_default`, `READ COMMITTED` re-evaluation after a lock wait for docs that were not locked (the old code lost those updates too). Foreign keys WERE reproduced after all (a child needs its parent, a parent with children cannot be deleted, parents are inserted first): Mongo has none, and a ledger write for a learner deleted a moment earlier must still be refused.

## 5. Milestones and exit gates

Each milestone ends with a gate. The gate numbers are the pre-migration results from CLAUDE.md; they must come out the same on the ported code.

- **M0 - safety net (no app code).** Worktree + branch (done). Test image with `pymongo`. `tests/lib/scratch_mongo.sh` (start / stop / URI / the guard). `create-app-db.sh dusu prod --no-bucket` on the shared Mongo + a probe with the scoped user (create index, a transaction, a partial unique index, a TTL-free write, `mongodump`) in a throwaway collection, cleaned up. Rehearsal: production dump -> scratch Postgres -> ETL -> scratch Mongo -> verifier (counts, a content hash per row, every JSON column deep-equal, every index present). **Shadow comparison:** the OLD app on the restored Postgres and the NEW app on the migrated Mongo are asked the same read-only questions for all 22 real learners (tokens minted on the scratch stack only): `/me`, `/leaderboard`, `/league`, planner Today / lists, keys status, notifications prefs, grammar state, RI state ... and the responses are diffed. *Gate:* zero differences that are not a documented, intended one (ms timestamps).

## 6. Risks

| Risk | Mitigation |
|---|---|
| Subtle semantic drift (NULL order, `!=`, unique-with-NULL, dates) | section 4 table; differential test vs real Postgres; golden master for `db.py`; the existing suites; the shadow comparison on real data |
| Lost update / deadlock because Mongo has no row lock | keyed locks + lock timeout + WriteConflict as a loud net; concurrency tests; single worker (D9) |
| A duplicate key aborts a Mongo transaction (no savepoints) | the 5 savepoint sites rewritten to insert-or-ignore; `IntegrityError` handling reviewed at all 15 catch sites |
| The shared Mongo is now a single point of failure for RootEd (a school's data), Yahin and DuSu; noisy neighbour; its WiredTiger cache is not capped (host RAM is tight) | scoped user, indexed hot paths, bounded polling in the loops (soak test), nothing DuSu does can reach another database; **owner's call:** cap `--wiredTigerCacheSizeGB` (their PLAN.md lists it as open) |
| Millisecond timestamps vs microsecond | truncate on write; fake-clock tests use whole seconds - checked |
| Rollback after users wrote to Mongo loses that data | cutover in a quiet window, verify within minutes, Postgres untouched for >= 7 days; if a rollback is ever needed after real writes, the ETL logic reversed for the few tables that changed |
| Mutation suites (`mutants.sh`) patch exact SQL source text and will stop applying | not a gate for the migration; re-derived per module afterwards (a new mutant set for `store` is part of M1) |
| Memory on this host while testing (Docker VM 8 GB, 4 GB available) | scratch Mongo with a 0.25 GB cache + `--memory`; no parallel mongo scratch runs beyond two |

## 7. Cutover runbook (M8 - DONE 2026-11-16 19:42 IST; kept as the record and as the rollback procedure)

Total downtime is the time between stopping the old backend and the new one answering - about a minute if the commands are ready. Everything before step 3 is safe to do while the app is serving. **Never print the password**: it is read from `~/Desktop/RootEd_ALL/shared-services/creds/dusu-prod.env` (48 letters and digits) and only ever travels through `--env-file` or a command substitution into a file.

0. **Preconditions** (all measured before asking for the go): the final image tested as built (`tests/store/baked_all.sh`, `BROWSER_IMAGE=... tests/store/browser_all.sh`, `tests/store/soak.sh`); the pre-flight on the real server (`tests/store/preflight_shared.py`) and the production-shaped rehearsal passed; an ETL rehearsal on a dump taken the same day (`tests/store/etl_rehearsal.sh`) identical. Quick look: `docker ps` shows `dusu-backend-1`, `dusu-db-1` and `rooted-mongo` up; `docker network inspect rooted-shared-net`; `docker image inspect dusu-backend:mongo-rc4`.
1. **Rollback artefacts.** `docker tag dusu-backend:latest dusu-backend:pre-mongo` (= the image production runs now); `cp ~/Desktop/DuSu/docker-compose.yml ~/dusu-backups/docker-compose.yml.before-mongo-<ts>`.
2. **Quiet window.** `docker logs dusu-backend-1 --since 15m | grep -c ws/interview` (a handful of chats is fine; nothing is lost either way - the stop is a clean shutdown and the browser reconnects).
3. **Stop writes.** `cd ~/Desktop/DuSu && docker compose stop backend` (Postgres keeps running). From here the app is down.
4. **Final dump of the old database** (rollback + audit): `( umask 077; docker exec dusu-db-1 sh -c 'pg_dump --no-owner --no-acl -U "$POSTGRES_USER" -d "$POSTGRES_DB"' | gzip > ~/dusu-backups/dusu-before-mongo-<ts>.sql.gz )`.
5. **The final ETL**, a one-off container on BOTH networks (the compose network for `db`, the shared one for Mongo): `docker create --name dusu-etl --network dusu_default --env-file ~/Desktop/RootEd_ALL/shared-services/creds/dusu-prod.env --env-file ~/Desktop/DuSu/.env -e PYTHONUNBUFFERED=1 -e SESSION_SECRET=etl -v ~/Desktop/DuSu-mongo/backend:/app:ro dusu-mongo-test sh -c 'python /app/scripts/pg_to_mongo.py --src "postgresql://$POSTGRES_USER:$POSTGRES_PASSWORD@db:5432/$POSTGRES_DB" --replace --verify'` then `docker network connect rooted-shared-net dusu-etl`, `docker start -a dusu-etl`, `docker rm dusu-etl`. `--replace` makes the target equal the source (the database holds nothing real before this); `--verify` compares EVERY row. The same command with `--dry-run` instead of `--replace --verify` was run against the live Postgres on 2026-11-16 (read-only; 491 rows read, nothing written). **Abort here** (the verifier prints a difference, or anything else looks wrong) = `docker compose start backend`: nothing was changed on the old side.
6. **Config.** Back up, then copy the new `docker-compose.yml`, `docker-compose.dev.yml`, `.env.example` and `backend/.env.example` from the migration branch into `~/Desktop/DuSu` (so any later `docker compose up` keeps pointing at Mongo); add the password to the root `.env` without printing it: `grep -q '^DUSU_MONGO_PASSWORD=' .env || printf '\nDUSU_MONGO_PASSWORD=%s\n' "$(grep '^MONGO_PASSWORD=' ~/Desktop/RootEd_ALL/shared-services/creds/dusu-prod.env | cut -d= -f2-)" >> .env`.
7. **Start the new image.** `docker tag dusu-backend:mongo-rc4 dusu-backend:latest` (the image that ran the tests IS the image that runs), `cd ~/Desktop/DuSu && docker compose up -d --no-deps backend` (only the backend is recreated; `dusu-db-1` keeps running behind its profile as the rollback).

The owner opens the installed app on a phone: sign in, Home, a chat, My Day.
9. **Rollback** (written before the old Postgres was deleted on 2026-11-16; it is now a RESTORE FROM THE FINAL DUMP, anything written to Mongo since step 7 is lost): `docker compose stop backend`; copy `~/dusu-backups/docker-compose.yml.before-mongo-<ts>` over `~/Desktop/DuSu/docker-compose.yml`; `docker tag dusu-backend:pre-mongo dusu-backend:latest`; `docker compose up -d db` (an empty new volume; the root `.env` still holds `POSTGRES_*`); `gunzip -c ~/dusu-backups/dusu-before-mongo-<ts>.sql.gz | docker exec -i dusu-db-1 sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'`; `docker compose up -d --no-deps backend`.
