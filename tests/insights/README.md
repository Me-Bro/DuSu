# tests/insights - first-run funnel counters, "Reserve my plan", and the cache validators of `GET /`

Built 2026-10-30 for the product / UI audit (`DUSU_AUDIT_FIX_PLAN.md`, items P1-10, P0-2, P0-3). Everything here runs on a **scratch Postgres on an internal Docker network** (no route out, never the app's
own database) with every provider key blanked.

| Tier | What it proves | Run |
|---|---|---|
| 1 `unit.py` | the event allow-lists (a browser can never send a server-only milestone), every value fits its column, the plan / price-opinion cleaners accept exactly the allowed values (hostile input included), the `If-None-Match` logic (strong, weak, list, `*`, junk), the build-once page cache, the "versioned asset" rule; **the counters are today's** (`db._live_counters`: practised today / yesterday / two days ago / eight days ago / never / no row, five minutes after IST midnight, the IST day vs the UTC day, and `_state()` carrying them - 10 checks) | `tests/insights/run.sh unit.py` |
| 2 `selftest.py` | the real HTTP layer: old -> new schema rehearsal; `POST /ev` (login, allow-list, always a quiet 204, idempotent, restart-safe, 25 at once = one row, rate limit, kill switch); the server-side hooks (`/me` active day, `/keys/save` -> key1 / key2); `POST/GET /plans/interest` (validation, idempotent, an opinion never erased, isolation between learners, blocked account, rate limit); the owner's funnel (cohort rule, per-step counts, Day-1 / Day-7 return computed exactly, plan interest, empty database, clamped `days`, owner-only); Ranks (only learners with XP are on the all-time board; the 0-XP learner's own row is pinned with its true rank); **the counters are today's** (a learner last active 8 days ago has streak 0 and 0 sessions today in `/me`, in `growth` and on the owner dashboard while 4 and 2 stay stored; yesterday keeps the streak and starts at 0 sessions; today shows both; a read never writes); data rights (account delete + the owner's wipe); a failing database never raises into a request; `GET /` ETag / 304 for the front door **and every other door to the shell** (deep links, a signed-out `/leaderboard` / `/league` navigation) and the cache headers of versioned assets | `tests/insights/run.sh selftest.py` |
| 2b `ws_selftest.py` | the two hooks in the real `/ws/interview` handler: the first spoken sentence, and a finished session with at least one real turn (not an opened chat, not a blank line, not Learn); a second session never duplicates; the kill switch; a hook that raises never breaks the chat | `tests/insights/run.sh ws_selftest.py` |
| 3 `mutants.sh` | **42 planted bugs** (M42: the support address written into the page's markup again - Cloudflare rewrites it and drops the page's ETag; M39-M41: the page's ETag strong again, no content type registered for the font / WebP logo, the page's own weak tag never matching its copy; M33-M38: yesterday's sessions shown as today's, a dead streak alive, the UTC day, `/me` / the Home chip / the dashboard reading the stored numbers), one at a time in a COPY of the backend (a milestone outside the allow-list, no in-memory memory, an overwritten first time, an erased price opinion, any string is a plan, a cohort that ignores when tracking began, Day-1 counting any later day, deletion that forgets a table or the in-memory memory, a browser that can send server-only events, no login / rate limit / kill switch, a reservation redirected by a body field, everybody's reservations, a blocked account that can still reserve, the hooks removed or misplaced, a weak ETag that never matches, a page never refreshed, every asset "immutable", a 304 without validators, an open funnel, two doors to the shell without validators, the Ranks filter removed, `db.delete_user` forgetting the insights rows ...): the first tier that fails catches it | `tests/insights/mutants.sh [M3 M5 ...]` |

`INS_BACKEND=<path>` runs against a copy of the backend (what `mutants.sh` does); `INS_BACKEND=baked INS_TEST_IMAGE=dusu-backend:latest` runs against the code inside a built image.

What the counters store (and the privacy page says): a milestone **name and a time** per learner (written once), the **days** the app was opened, and the plan a learner reserved with an optional "too high / fair /
great". No words, keys, recordings, device data or payment data. All of it is deleted with the account.

Found by these tests while building (kept as pins): `date + $1` is ambiguous to Postgres (`CAST(:n AS integer)`); changing `index()`'s signature broke its three internal callers - the SPA fallback for every deep link
among them - which only a test of the *other doors to the shell* sees; a lone `[]` for `price_feel` must be a 422, not "no opinion".
