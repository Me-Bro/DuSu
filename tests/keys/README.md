# Keys / Install / Community - test harness

Everything runs in Docker on **scratch** infrastructure - never the app's own `dusu-db-1`, never a real provider key (`run.sh` / `browser/run_real.sh` blank every key; the bind-mounted `backend/` holds the real `.env`) and **no route to the internet**: the scratch Postgres network is created `--internal`, so even a bug cannot spend a real key. Every AI provider is a **scripted fake** (`world.py`): the app's SDK clients and probes are pointed at an `httpx.MockTransport` through `openrouter_provider._http_client_factory`, and each answer is scripted per provider host + bearer key. The error bodies are synthetic (a day limit cannot be provoked on demand); `capture_real_errors.py` is the owner-run script that records real ones with the owner's own keys so the fixtures can be checked against reality.
Same shape as `tests/notify/` (see its README for the one-time Playwright / test-image setup).

## "AI busy" (30 Oct 2026) - what these tiers pin
* `unit.py` D3 / E: the second pass (a passing failure waits ~1.2-1.8 s and goes round ONCE more; a limit that ends in <= 5 s is waited out; never for a rejected key, a long limit, a deterministic refusal, a background caller or when the 30 s ceiling leaves no room), limits PER MODEL (Groq / Gemini, and OpenRouter's busy-upstream 429), the 404 model memory (per key, 30 min), the one safe log line (no key, no learner id, nothing the provider wrote), `kp.own` / `kp.retry_in`, and the `_is_quota` truth table.
* `ws_selftest.py`: "the AI did not answer" is never a `quota` frame (even when its text says 429), DuSu's own keys carry NO key rows, a failed turn gives its free daily turn back, a failed Face-to-Face turn takes the unanswered line back.
* `selftest.py` (`/health`): `models_gone`, `models_missing` (a configured id the provider no longer lists; an alias is never judged; an empty list is "don't know"), and the hourly tiny real chat call to DuSu's own keys (a key that LISTS models but is refused every chat - Google's 403 "free tier not available for this project" - reads `forbidden`, not `ok`).
* The browser half is `tests/daily_voice/browser/busy.spec.cjs` (see that README).
* `probe_models.py` is the owner-run tool: `docker run --rm -v "$PWD/backend":/app:ro -v "$PWD/tests":/tests:ro dusu-ri-test python /tests/keys/probe_models.py gemini openrouter [--once]` - which models REALLY answer the Home prompt with DuSu's own keys (status kinds, a bounded provider reason with anything key-shaped removed, latency, valid JSON, Devanagari share). It spends a few free-tier requests; run it when "AI busy" shows up.

## The validated walk (`chain_v3`, 16-17 Nov 2026) - what these tiers pin
The switch is `settings.chain_v3` (off / owner / on, needs `key_health`); `main.engine_level(email)` = 0 legacy walker, 1 per-key walker, 2 + the validated walk. Every tier is a fast one (scratch MongoDB + the scripted world), so they run FIRST in `mutants.sh`.
* `chain_unit.py` (159 checks, `tests/keys/run.sh chain_unit.py`): **A** the validators (`json_accept`: valid / wrong type / missing field / not JSON / a list / cut off at the token limit / numbers as strings; `chat_accept`); **B** the gate (a model held back per key AND per kind of call: 20 s doubling to 10 min, one good reply clears it, decays, bounded); **C** the walker - an unusable reply is a failure like any other: the NEXT PROVIDER answers in the same call with no pause, the model's siblings follow in a second pass, a held-back model is not asked again, every model held back is still asked (never zero attempts), nothing usable -> `BadReplyError` (state transient, never "your keys"), isolation between learners, the safe log line; **D** the engine levels (0 / 1 / 2) and that level 1 is exactly what it was; **E** Groq's reasoning settings (per-turn calls only, validated walk only; a model that answers 400 to them is remembered per model); **F** `assess` / `score` return the old failure shape (and stash `last_bad()`), the save-time probe wants a real answer (160 tokens; a 400 that names the reasoning settings is retried without them; an empty reply cut off by the limit counts); **G** `/level/test/submit`'s body is bounded; **H** model health (success rate, speed, breaker: three failures to ANSWER in a row open it for 60 s, ONE probe, doubling to 5 min; unusable replies do not count toward it) and the order of the providers (bands, so close scores keep the configured order), plus the time budgets against the scripted world (an interactive JSON turn gives an attempt 0.5 s here - 11 s in production - the LAST provider gets what is left, a heavy call keeps its long limit, the walk ends at its ceiling).
* `chain_selftest.py` (30): the HTTP layer on a scratch MongoDB - the owner's switch and the model-health card, `/lesson/evaluate` (the sentinel is a 502 with a `kp`, not a 200), `/level/test/submit` (422 bounds, `passed` = the unlock's rule, "eighty" asks the next model, a reply nobody could use records NOTHING), `/leveltest/gen` (one walk, not three attempts), saving a key whose models answer with nothing (stored as `unknown`, never working; a deep Test says `unreachable`).
* `chain_ws.py` (21): the real `/ws/interview` handler - Home / Daily Talk / Face-to-Face with Groq answering prose, a missing field, a cut-off object or nothing: the learner gets the NEXT provider's reply in the same turn; nothing usable -> the built-in answer after ONE pass (not the old retry of the first model); chain_v3 OFF = the old behaviour exactly.
* `mutants.sh M70-M116`: 47 planted bugs for all of the above; the first tier that fails catches it. `world.py` records every request body (`world.bodies`) and enforces the request's read timeout like a real transport (httpx's MockTransport does not).
* Gotchas: a test that wants ONE request per turn uses `cool=False` (no pause, no second pass - the random 1.2-1.8 s pause can otherwise trigger a second pass inside a short test ceiling); a timing test must not run in parallel with other docker suites; the early-held-back rule means a second call in a test often skips the model the first call broke - clear `gate._bad` (or age it) between calls when the test needs it asked again.

## How the fake world works
`e2e_server.py` also has two behaviours for the "AI busy" work: `chat_down` (chat answers 503 but the zero-quota key checks answer ok: the KEY is fine, the AI is not) and `forbidden` (chat answers 403 with Google's "free tier is not available for this project" while the list still answers ok), and a test-only `POST /__world/serverhealth` that looks at DuSu's own keys at once (the real loop does it every 10 minutes).

`world.World` records every call as `(provider, key, kind, model)` and answers from a script: `world.on(provider, key, R, R, ...)` (the LAST step repeats; `kind="models"|"key"|"chat"` scripts one endpoint only); `world.default_chat` / `world.chat_reply(messages, provider, key)` answer anything unscripted. `e2e_server.py` wraps it as `Control`: a behaviour per provider (or exact key) - `ok / limited / limited_min / upstream / invalid / expired / down / unreachable` - flipped from the browser spec through test-only routes (`POST /__world/behave|reset|calls|flush|pushes`, never part of the app). The push service is a fake too (`/__world/pushes` returns what it was asked to send).

## Notes that cost time once
* A concurrent test only interleaves if the fake takes time: an immediate answer lets one task finish before the next starts (`R(200, ..., delay=0.15)`).
* `ctxFor(... { seed })` in `browser/lib.cjs`: the installed context seeds ONE time per context; pass `seed` AFTER the defaults (`Object.assign({...}, o, { seed })`) or a caller's seed replaces them.
* The re-check endpoint is limited to 4 a minute per learner and saving to 8: a spec that clicks Test / Check all more than that must use another learner (or expect the "wait a moment" message).
* A learner whose keys were left rejected by an earlier section gets the key pop-up on Home load (rightly): dismiss it first (`L.closePop`) or use a fresh learner.
* The new features default to Hindi unless the learner chose English on the server: the browser specs call `POST /lang` for every learner first.
* The key engine is switched per learner (`key_health` off / owner / on): with it OFF the walker, the precedence and every frame are exactly today's - tiers 2, 3 and 6 pin that.
