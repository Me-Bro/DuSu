# Keys / Install / Community - test harness

Everything runs in Docker on **scratch** infrastructure - never the app's own `dusu-db-1`, never a real provider key (`run.sh` / `browser/run_real.sh` blank every key; the bind-mounted `backend/` holds the real `.env`) and **no route to the internet**: the scratch Postgres network is created `--internal`, so even a bug cannot spend a real key. Every AI provider is a **scripted fake** (`world.py`): the app's SDK clients and probes are pointed at an `httpx.MockTransport` through `openrouter_provider._http_client_factory`, and each answer is scripted per provider host + bearer key. The error bodies are synthetic (a day limit cannot be provoked on demand); `capture_real_errors.py` is the owner-run script that records real ones with the owner's own keys so the fixtures can be checked against reality.
Same shape as `tests/notify/` (see its README for the one-time Playwright / test-image setup).

## How the fake world works
`world.World` records every call as `(provider, key, kind, model)` and answers from a script: `world.on(provider, key, R, R, ...)` (the LAST step repeats; `kind="models"|"key"|"chat"` scripts one endpoint only); `world.default_chat` / `world.chat_reply(messages, provider, key)` answer anything unscripted. `e2e_server.py` wraps it as `Control`: a behaviour per provider (or exact key) - `ok / limited / limited_min / upstream / invalid / expired / down / unreachable` - flipped from the browser spec through test-only routes (`POST /__world/behave|reset|calls|flush|pushes`, never part of the app). The push service is a fake too (`/__world/pushes` returns what it was asked to send).

## Notes that cost time once
* A concurrent test only interleaves if the fake takes time: an immediate answer lets one task finish before the next starts (`R(200, ..., delay=0.15)`).
* `ctxFor(... { seed })` in `browser/lib.cjs`: the installed context seeds ONE time per context; pass `seed` AFTER the defaults (`Object.assign({...}, o, { seed })`) or a caller's seed replaces them.
* The re-check endpoint is limited to 4 a minute per learner and saving to 8: a spec that clicks Test / Check all more than that must use another learner (or expect the "wait a moment" message).
* A learner whose keys were left rejected by an earlier section gets the key pop-up on Home load (rightly): dismiss it first (`L.closePop`) or use a fresh learner.
* The new features default to Hindi unless the learner chose English on the server: the browser specs call `POST /lang` for every learner first.
* The key engine is switched per learner (`key_health` off / owner / on): with it OFF the walker, the precedence and every frame are exactly today's - tiers 2, 3 and 6 pin that.
