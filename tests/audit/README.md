# tests/audit - a product / UI review harness, and the verification of its findings

`walk.cjs`, `flows.cjs` and the other review specs assert nothing: they make the REAL app look and behave the way a learner meets it, photograph every screen and measure it. Built 2026-10-30 for the
product-owner + UI-officer audit (`DUSU_PRODUCT_UI_AUDIT_2026-10-30.md`). **`verify.cjs` is the exception: it ASSERTS** - one check per audit finding that was fixed (`DUSU_AUDIT_FIX_PLAN.md`), each labelled with its audit item.
Scratch infrastructure only - an internal Docker network with no route out, a scratch Postgres, a fake model, fake keys. Never production.

| File | What it does |
|---|---|
| `up.sh` / `down.sh` | start / remove the scratch app (Postgres + the real app + `audit_server.py`). It stays up between runs. `AUDIT_IMAGE=dusu-backend:latest AUDIT_BACKEND=baked tests/audit/up.sh` runs the real app from the code INSIDE a built image instead of the working tree - what a deploy tests (`AUDIT_BACKEND=<path>` = a copy, for planted bugs) |
| `audit_server.py` | rollout switches set like PRODUCTION (read 2026-10-30), learners in different states (`newbie`, `keyed`, `active`, `lapsed`, `owner`, nine league rivals), a fake model that answers each kind of prompt, gzip like Cloudflare |
| `spec.sh <spec>` | run one spec in a real Chromium against the running app (`AUD_ENV="A=1 B=2"` passes env vars) |
| `lib.cjs` | contexts (fonts served locally, fake speech), `capture()` = screenshot + measurements (overflow, tap targets, tiny text, contrast, names, alt, console, failed requests) |
| `walk.cjs` | every screen x phone / small phone / desktop / Hindi / new learner / lapsed learner (`PHASES=A,B,C,D,E,G`) |
| `flows.cjs` | what a learner DOES: first run, conversation, Daily Talk, Learn, Interview, My Day forms, the owner dashboard, the features about to go live (`FLOWS=A,B,...`) |
| `race.cjs` | cold deep links on a device with no cached state |
| `a11y.cjs` | keyboard order + focus rings, offline behaviour |
| `widths.cjs` | tablet / mid-range desktop widths |
| `live.sh` + `live.cjs` | cold-open performance of the LIVE public page (read-only: loads the home page like a visitor) under CPU + network throttling |
| `live_gis.cjs` | READ-ONLY, against the LIVE site: does Google's own "Sign in with Google" button render on the real sign-in page? The audit moved Google's script from the page head to a lazy load (`loadGIS`), and the offline sandbox has no route to Google, so only the live site can show the button still appears. Run it BEFORE a deploy as a control (the old page must pass) and after: `LIVE_URLS="https://dusu.ranabrothers.online/ https://dusu.ruralrootcloud.com/" node live_gis.cjs` from the Playwright image (see `live.sh` for the docker line) |
| `slice.py` | cut a tall screenshot into readable slices |
| `verify.cjs` | **assertions** for the audit fixes: S smoke (the page loads with no script error), K first-run Keys wizard, R cold deep links, P plans + Reserve my plan, F first-run overlays + a short chat's result, O offline wording + retry, H Home / names / Practice hub / empty states / copy, N retired names + static facts about the shipped page, U the UI system (lining numerals measured in pixels, type floor, header, 44 px targets on 34 screens, contrast, My Day, icons, tabs, badges, Ranks, Journey, owner dashboard, mood buttons, the Home language pill), W the weight of the first visit (what the page ASKS for, and the sign-in delay note's timing), V pins from the independent review (a failing `/keys/status` is not retried in a loop, history signals, a saved price opinion, a shared phone ...), Y the fresh-eyes visual review's fixes (a word cut in half, a dim button with no reason, five equal bars, a streak that died shown as alive, a Grammar button wrapping to five lines ... - 41 checks, each one finding from a reviewer who had not seen the earlier work), X the XSS canary. `AUD_ENV="ONLY=K,R" tests/audit/spec.sh verify.cjs`; restart the app with `down.sh` / `up.sh` first when server code changed. **`OLD_HTML=/repo/tests/audit/.out/before.html` makes U / W / X run against the page as it was before the fixes - they must FAIL there** (that is how each check is shown to discriminate; make that file with the command in `perf.cjs`'s header). **Y is shown the same way against `.out/pre-vr.html` - the page as it was before the visual-review fixes, with the three placeholders (`__GOOGLE_CLIENT_ID__`, `__AUTH_ENABLED__`, `__MAX_SESSIONS__`) substituted as `"audit-client"` / `true` / `20`, otherwise it dies at load; 33 of its 41 checks fail there** (the 8 that pass are pins - the header stays one row - or server-side counters, which an HTML swap cannot undo; `tests/insights/mutants.sh` M33-M38 cover those). A screenshot file is overwritten by the LAST run: look at the pictures only after the run you mean. Every section leaves the scratch database as it found it, so the whole file can be run again |
| `perf.cjs` | first-visit weight of the sign-in screen, before vs after, under no / Slow-4G / 3G throttling (requests, KB by type, FCP, LCP, load). `AUD_ENV="BEFORE_HTML=/repo/tests/audit/.out/before.html" tests/audit/spec.sh perf.cjs` |
| `mutants.py` + `mutants.sh` | **planted bugs for the client side**: 48 deliberately broken copies of the page (m01-m28 for the audit fixes and the independent review; **m29-m47 for the visual-review fixes, all caught by section Y**: the plan hint always hidden, the plan ring never filling, My Day's summary cut again, the alias cut mid-word, the one-day chart, ISO dates, the loading dots in an empty result, the Grammar buttons side by side, the floating underline, Remove like Change, the dim avatar initial, the mood row wrapping, no "not on this week's board" row, "You are <alias>", the guide not scrolling, the sliders icon, "ज़्यादा", two "Consistent Speaker", "DUSU"; history always true / never, the deep-link wait removed, `plural`, the time style, the key-prefix map swapped, Reserve saving another plan, a short chat scored, an unescaped model string, the language pill back at the bottom, numerals back to old-style, 40 px My Day buttons, no hung-/me fallback, the alias back in the header, no badge hints, no empty-state button, rewards before speaking, a font from Google, the funnel card missing, plus a harmless CONTROL that must stay green). `tests/audit/mutants.sh` serves each one (`HTML_OVERRIDE`) to the verify sections that must catch it; every one must FAIL and the control must PASS (m48 / m49, found by the live checks: the Help screen's support address never filled in, and written into the markup again - Cloudflare rewrites an address it finds in the page, injects a blocking script and drops the page's ETag) |
| `compare.py` | before / after of two `results-walk-*.json` sweeps (tiny text, tap targets, contrast, overflow, errors, screen heights); `--screens` lists any screen that got worse |
| `innerhtml_scan.py` | static map of every HTML-injecting sink in the page and the interpolations that are not visibly escaped (audit E-1); the dynamic check is the canary in `verify.cjs` |

The audit server also has test-only control routes (`/__audit/settings`, `/reset` of the funnel / plan tables, `/reset_learner`, `/hook`, `/chatdone`) so a spec can be run twice on the same app.
Screenshots and `results-*.json` land in `~/.cache/dusu-audit-shots/` (override with `OUT_DIR`). `.fonts/` (the app's two Google fonts + Noto Sans Devanagari, copied once on the host because the scratch
network has no internet) and `.out/` (session tokens for the seeded learners) are git-ignored.

Gotchas: the app routes a cold deep link BEFORE `/me` answers, so a spec that opens `/my-day` as its first page on a fresh context hits the "isn't available" race (a real bug - see the report); open `/`
first. `usageInc`-style counters are no-ops for unlimited learners. The fake model's replies are canned: judge layout and flow from these shots, never AI quality.
